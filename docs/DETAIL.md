# 小说工作台（dsh-novel-kit）

## 它是做什么的

一个给**长篇连载**和**同人写作**用的工作台插件：把「剧情决策 / 世界契约 / 长篇记忆 / 文风」四段写作依据装配好再动笔，写完后的正文、剧情账、记忆卡在同一个可恢复事务里落账。

装它一个就够，不需要另外的插件。

## 装完你会得到

- **七页工作台**：书桌、正文、决策、记忆、风格、同人、资料；
- **一条章节链**：计划 → 开章 → 写 → 检查 → 落账，中断可恢复；
- **四段写作依据**：各有字数预算与来源修订号，依据变了会明确提示；
- **文风档案**：导入你喜欢的小说，得到句长/段长/对话比区间、避免词与决策倾向；
- **同人世界契约**：人物、称呼矩阵、事实、关系、禁忌、秘密，逐条审阅后应用；
- **检查能定位**：禁忌词、与原著雷同、疑似写错的名字、称呼不符、文风越界，点一下选中那句；
- **草稿保护**：切作品不静默丢稿、保存互斥、回包校验归属；
- **默认关闭**：不开总开关，它不会往你的会话里塞任何工具。

## 适合谁

- 写到二三十章开始「接不上」的连载作者；
- 想让人物说话、称呼、设定不前后矛盾的作者；
- 想让 AI 写得像自己、而不是像通用的 AI 的写手；
- 写同人，需要把原著事实钉死、还能逐条审阅的作者。

## 一章怎么走

```text
novel_plan → novel_chapter_start → novel_chapter_write → novel_chapter_finish
```

收尾前先跑确定性检查：禁忌词、与原著连续相同、疑似写错名字、称呼矩阵、文风区间。blocker 不落账；通过后正文、剧情段落、记忆卡在同一个事务里提交，返回回执；中断了用 `novel_chapter_resume` 接上。

## 原创与同人是两条路

- **原创**：导入只影响文笔，不注入世界事实；即使误绑同人项目也不会加载世界段；
- **同人**：必须绑定原著，且世界契约已由作者确认；否则开章直接拒绝，不会无约束硬写。

同一部作品两边导入只存一份原文（按内容哈希去重），文风与世界观互不污染。

## 数据在哪

全部在工作区的普通文件里，可备份、可 git 管理：

```text
<workspace>/.dsh-novel-kit/       # 项目设置、原文、文风、世界契约、会话、事务、操作日志
<workspace>/.dsh-novel-beat/      # 剧情段落与拍板
<workspace>/.dsh-novel-fade/      # 记忆卡
```

## 边界

- 当前版本仍在迭代，真实界面验收与写盘故障注入尚未完成；
- 锁是单 Host 进程内锁，多进程同时写同一工作区未覆盖；
- 旧版插件的文风库与同人项目为只读兼容，需要工作台自有档案时请重新导入并确认。
